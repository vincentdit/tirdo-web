# TIRDO Web Platform

A dynamic, containerised rebuild of the **TIRDO** website (tirdo.or.tz), re-organised
following the information architecture of the **from other sites** and keeping TIRDO's
brand colours (primary blue `#2d4a84`, gold accent `#e8a33d`).

Everything runs locally with **Docker Desktop** on Windows and is driven from **PowerShell**.

---

## 1. Architecture — the 14 layers

| Layer | Technology | Service in `docker-compose.yml` | Runs at (local) |
|-------|-----------|-------------------------------|-----------------|
| Frontend | Next.js 14 + TypeScript (App Router) | `frontend` | http://localhost |
| UI | Tailwind CSS + shadcn/ui-style components | (in `frontend`) | — |
| Backend | Next.js API routes (`/api/contact`, `/api/search`) | (in `frontend`) | — |
| Database | PostgreSQL 16 | `postgres` | internal :5432 |
| CMS | Strapi 5 | `cms` | http://localhost:1337/admin |
| Authentication | Keycloak 26 | `keycloak` | http://localhost:8080/auth |
| File storage | MinIO (S3-compatible) | `minio` + `minio-init` | http://localhost:9001 (console) |
| Search | OpenSearch 2 + Dashboards | `opensearch`, `opensearch-dashboards` | http://localhost:5601 |
| Web server | Nginx | `nginx` | http://localhost (:80) |
| Analytics | Matomo (+ MariaDB) | `matomo`, `mariadb` | http://localhost:8090 |
| Containers | Docker / Docker Compose | — | — |
| OS | Ubuntu Server LTS (deploy target) | — | — |
| Version control | GitHub | `.github/` | — |
| CI/CD | GitHub Actions | `.github/workflows/ci.yml` | — |

**How the pieces talk to each other**

```
 Browser ──▶ Nginx :80 ──▶ Next.js (frontend)
                              │  server-side fetch
                              ▼
                        Strapi CMS :1337 ──▶ PostgreSQL
                              │  uploads         ▲
                              ▼                  │ lifecycle sync
                           MinIO (S3)      OpenSearch ◀── /api/search
 Keycloak (SSO)  ·  Matomo (analytics tag)  ·  MariaDB (Matomo DB)
```

- The **frontend** reads content from **Strapi** (server-side over the internal Docker
  network, client-side via `http://localhost:1337`). If Strapi is still booting, the site
  falls back to bundled sample content so it is **never blank**.
- **Strapi** stores structured content in **PostgreSQL** and uploaded media in **MinIO**.
- On every content create/update, a **Strapi lifecycle hook** pushes the record into
  **OpenSearch**; the site's `/api/search` queries OpenSearch (with a local fallback).
- **Keycloak** provides single sign-on (realm `tirdo`, client `tirdo-web`) for e-Services.
- **Matomo** collects privacy-friendly analytics via a tag injected by the frontend.
- **Nginx** is the single public entry point (port 80) and the place to add TLS in prod.

## 2. Prerequisites

- **Docker Desktop** for Windows (WSL2 backend) — running.
- **PowerShell 5.1+** (Windows PowerShell or PowerShell 7).
- ~6 GB free RAM for the full stack (OpenSearch + Keycloak are the heavy ones).

## 3. Quick start (PowerShell)

```powershell
# from the project root
./scripts/setup.ps1
```

`setup.ps1` will:
1. Check Docker is running.
2. Create `.env` from `.env.example` and fill in strong random secrets.
3. Build all images and start the stack (`docker compose up -d --build`).
4. Print every service URL.

> **First run takes a few minutes** — Strapi builds its admin panel and OpenSearch/Keycloak
> initialise. Watch progress with `./scripts/dev.ps1 logs cms`.

If you prefer the raw command:

```powershell
Copy-Item .env.example .env      # then edit secrets
docker compose up -d --build
```

### Everyday commands

```powershell
./scripts/dev.ps1 ps             # status
./scripts/dev.ps1 logs cms       # follow a service's logs
./scripts/dev.ps1 restart frontend
./scripts/dev.ps1 seed           # (re)seed demo content
./scripts/dev.ps1 reindex        # rebuild the OpenSearch index
./scripts/dev.ps1 down           # stop
./scripts/dev.ps1 nuke           # stop + delete all volumes (fresh start)
```

## 4. Service URLs & first-time setup

| Service | URL | Notes |
|---------|-----|-------|
| Public website | http://localhost | The TIRDO site |
| Strapi CMS | http://localhost:1337/admin | Create the admin user on first visit |
| Keycloak | http://localhost:8080/auth | Admin login from `.env` (`KEYCLOAK_ADMIN`) |
| MinIO console | http://localhost:9001 | Login from `.env` (`MINIO_ROOT_USER`) |
| OpenSearch Dashboards | http://localhost:5601 | Explore the `tirdo-content` index |
| Matomo | http://localhost:8090 | Runs a short install wizard on first visit |

All credentials live in your **`.env`** file (generated by `setup.ps1`).

**Matomo first-run:** complete the wizard using DB host `mariadb`, database/user/password from
`.env` (`MATOMO_DB_*`). Create site #1 with URL `http://localhost`. The frontend already sends
events to `http://localhost:8090` (see `NEXT_PUBLIC_MATOMO_*`).

## 5. Managing content

Strapi seeds demo content automatically (`SEED_DATA=true`). To manage it:

1. Open http://localhost:1337/admin and create your administrator account.
2. Edit **News Articles, Projects, Publications, Departments, Services, Pages**.
3. Publish — the frontend picks up changes within ~60s (ISR revalidation), and the record is
   automatically indexed into OpenSearch.
4. Uploaded media is stored in **MinIO** and served from `http://localhost:9000/tirdo-media/...`.

Content types live in `cms/src/api/*` and are easy to extend.

## 7. CI/CD (GitHub Actions)

`.github/workflows/ci.yml` runs on push/PR:
- **frontend**: `npm ci`, lint, `tsc --noEmit`, `next build`.
- **cms**: install + type-check.
- **docker**: `docker compose config` validation + image build.
- **deploy**: a stub for deploying to your **Ubuntu Server LTS** host over SSH — fill in
  `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY` secrets and uncomment the step.

---

## 8. Going to production (Ubuntu Server LTS)

1. Point DNS at your server; put real values in `.env` (rotate **all** secrets).
2. Terminate TLS at Nginx (add a `443` server block + certs, e.g. Let's Encrypt / certbot).
3. Front the admin services (Strapi, Keycloak, MinIO, Matomo) with subdomains and TLS instead
   of raw host ports, and set `KC_HOSTNAME` / `STRAPI_PUBLIC_URL` accordingly.
4. Set `NODE_ENV=production`, disable Strapi's `SEED_DATA`, and take regular Postgres backups.
5. Deploy with `docker compose up -d --build` from CI.

---

## 9. Notes & design decisions

- The frontend **degrades gracefully**: bundled sample content and a local search fallback mean
  the site works even before the CMS/OpenSearch are ready.
- Networking is **port-based for local dev** (admin consoles on their own ports) to avoid
  reverse-proxy base-path issues; Nginx fronts the public site and is where you add TLS.
- Brand colours are defined once as CSS variables in `frontend/src/app/globals.css`.
- Verified locally: the Next.js build compiles all routes, and Strapi boots, seeds 28 records,
  sets public API permissions, and serves the REST API (checked against SQLite; production uses
  PostgreSQL).
